# Code and architecture

## Actual stack

Observed in `package.json` / `bun.lock` on 2026-10-30:

- TanStack Start 1.168 (`@tanstack/react-start`), TanStack Router 1.170, React 19.2, Vite 8.1, Tailwind CSS 4.2, GSAP 3.15, three.js 0.186 with `@react-three/fiber` 9, `lucide-react`. The `/cartao` Silver Light Trace is plain CSS (`@paper-design/shaders` and LiquidMetal were removed).
- Strict TypeScript 5.8 (`tsconfig.json`, `@/*` → `src/*`).
- `@lovable.dev/vite-tanstack-config` 2.26 owns the Vite plugin stack (TanStack Start, React, Tailwind, tsconfig paths, Nitro build targeting Cloudflare, Lovable error logger). `vite.config.ts` only adds the `__ZURY_PHOTOS__` define and redirects the server entry to `src/server.ts`.
- Build output: Nitro → `.output/` (Cloudflare worker); local preview via Wrangler 4 with compatibility date `2026-10-19`.
- Package manager: Bun (`bun.lock`, `bunfig.toml`). The local ZIP delivery uses Node 24 LTS + npm with its own `package-lock.json` (not versioned here; see `README.md`).
- Hosting/sync: Lovable project connected to GitHub `main`.

## Boundaries and flow

- Static marketing site rendered by TanStack Start SSR. No API routes, server functions, authentication or persistence exist.
- Presentation reads data only from `src/lib/content.ts`. Contacts, channels and the WhatsApp destination (`contacts[0].href`) live there.
- Quote flow: `openQuote({ area, solution, trigger })` in `src/components/site/quote-menu.tsx` opens the dialog (event `zury:quote`), shared by `/` and `/cartao`. Four steps (`quote-steps.tsx`): 01 area, 02 solution of that area, 03 customer data, 04 confirmation. Solution items open it at step 03 with area and solution preselected; general CTAs open at step 01; every open resets the form. `src/lib/quote-form.mjs` (tested by `quote-form.test.mjs`) masks and validates the fields on the client (CPF or CNPJ check digits, including the alphanumeric CNPJ) and builds the `wa.me` link to `contacts[0].href`. Nothing is stored or sent to a ZURY server; the visitor's WhatsApp client receives the message.
- Server code: `src/server.ts` wraps the Start server entry to turn catastrophic SSR failures into the branded error page; `src/start.ts` adds error middleware and CSRF middleware. Errors are logged with `console.error` and reported through the Lovable runtime hook; no other logger exists.
- Build-time data: `vite.config.ts` enumerates `public/` photos into `__ZURY_PHOTOS__` (restart dev after adding photos).
- `isBenefitsPreviewEnabled` / `isReferralPreviewEnabled` (env `ZURY_BENEFITS_PREVIEW`, `ZURY_REFERRAL_PREVIEW`) remain in `content.ts` and are unit-tested, but no component gates on them now: both sections render in production by owner request (README).

## Data and migrations

No database, ORM or migrations: the product is a brochure site whose content is versioned in `src/lib/content.ts`. Toolkit Drizzle/PostgreSQL defaults do not apply. Revisit only if a confirmed need (stored leads, CMS) appears; record it in `PRODUCT.md` first.

## Decisions

| Decision                                                      | Reason                                                                                         | Revisit when              |
| ------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ------------------------- |
| TanStack Start on Lovable instead of the original Next.js app | Lovable runtime; the Next.js project and its Vercel deploy stay untouched (README, 2026-10-27) | Owner changes hosting     |
| Content centralized in `src/lib/content.ts`                   | Single literal source matching `ZURY-SITE-SPEC.md`                                             | A CMS is requested        |
| Motion ignores `prefers-reduced-motion`                       | Explicit owner decision (`PRODUCT.md`), no exceptions (the `/cartao` Silver Light Trace included) | Owner revokes it          |
| Quote dialog hands off to WhatsApp, no backend                | No server or data retention needed                                                             | Lead storage is requested |
| CSS Silver Light Trace (green external 1.25px loop with phase aligned once on mount/resume using the shared wall clock; one pass on hover/focus elsewhere); card CTA = header graphite glass/glow rectangle | Owner request (2026-11-03); LiquidMetal, `@paper-design/shaders` and the JS sequencer removed | Owner changes the effect  |
| Scroll-linked and looping motion stays on the compositor: hero video 720p (phone) / 1080p (desktop), all-keyframe, no animated `filter`; hero Velaris paused while transparent; infinite effects animate `transform`/`opacity` only (logo `.brand-shine-light`, COTAR `.quote-sweep`) and pause off-screen (`data-motion-paused`); the paused 3D solutions band also skips rendering (`content-visibility: hidden`, woken half a viewport early); one animation system per element; scroll offsets are read in the scroll event, never in a rAF after writes; `ScrollTrigger.refresh()` only on real page-height changes (ResizeObserver, fonts), never per image load | Mobile audit 2026-10-30: `background-position` loops in the always-visible navbar and the hidden WebGL loop forced a full main-thread frame on every vsync; GSAP parallax fought the CSS reveal on `.hero-copy`; per-image refreshes scrolled to 0 and back ~11 times per page, killing the touch fling; the header's rAF `scrollY` read forced a page layout per frame; 32 always-composited slices inflated layerize/commit everywhere | A new looping or scroll-linked effect is added |
