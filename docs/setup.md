## Delegation policy

- Prefer direct execution or a deterministic tool for simple work. Delegate only when context isolation, specialization or independent parallel work justify coordination; no fixed roster.
- Use the lightest available model that can meet the acceptance criteria: searches, inventories and mechanical edits → light; bounded implementation and behavior review → medium; security, ambiguous diagnosis, architecture → strongest. Select model/effort only through controls the client exposes; otherwise inherit and record it. Keep the main model; no proxies, API keys or provider changes.
- Each task gets: goal, minimal context, allowed files, dependencies, mutable resources, acceptance criteria, checks, return format.
- One writer per file. The coordinator owns `package.json`, `bun.lock`, Git operations, the dev server (port 5173) and Playwright runs; serialize anything sharing `.output/` or ports. Reviewers are read-only.
- The coordinator checks the diff and reruns checks before accepting a worker's result; confirm a worker stopped before taking over its files. Finite retries; escalate capability on poor results instead of repeating cheap attempts.
